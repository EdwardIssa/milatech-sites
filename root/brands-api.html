MILA for Brands · Developer docs

The MILA Sentiment API

Read-only aggregate sentiment over MILA’s public polls, for brand and research clients. Four endpoints serve per-poll sentiment, a trending snapshot, category snapshots, and poll search — the same honestly-counted votes the app shows, over HTTPS + JSON. Aggregates only: the API never returns voter identities or individual votes.

01 / Getting started

Base URL and authentication

Every request goes to the API base URL and carries your client key as a bearer token. Keys look like mila_live_… and carry the exclusive sentiment scope: a sentiment key works on the four endpoints below and nothing else, and no other kind of key works on them.

Base URL

https://tuedziedafdiwuuzzveo.supabase.co/functions/v1/api-v1

Authentication header (on every request)

Authorization: Bearer <your-key>

How to get a key

Keys are provisioned by MILA — there is no self-serve signup. Request access through the API waitlist and tell us what you want to measure; when your key is issued, the raw key is shown to you exactly once and is never stored on our side (only a SHA-256 hash is kept), so save it somewhere safe. Lost it? We revoke it and issue a new one.

Response envelope

Every successful response carries api_version ("v1") and generated_at (the ISO 8601 timestamp of that response, stamped fresh on each call) alongside the endpoint’s payload. Errors return { "error": { "code": …, "message": … } } — see §05 for the codes.

02 / The sample floor

Splits only when the sample earns them

The 10-ballot rule: a poll with fewer than 10 ballots returns vote counts only, with sample_state: "insufficient_sample" and no percentage fields anywhere in the response — they are omitted, not zeroed. Once a poll reaches 10 ballots, each option also carries share_percent and sample_state reads "sufficient". A 2-ballot poll is never dressed up as a 50/50 split.

This is the same small-sample honesty rule the MILA app applies in its own results, applied to the API exactly as-is. Ballot counts (sample_size) are always the full unified total: member and guest ballots across every format’s ballot tables. Only published, everyone-audience polls that are visible on their public /p/… page are served.

03 / Endpoints

Four read-only endpoints

All four require the sentiment scope. Paths below are relative to the base URL.

GET/v1/sentiment/polls/:id

One public poll’s sentiment.

  • :id — the poll’s UUID (the id in its https://app.milatech.tech/p/… link).
  • Returns poll: the standard poll payload described below. A poll that isn’t public returns 404 not_found — the API does not confirm private polls exist.
GET/v1/sentiment/trending

A trending snapshot: public polls in the app’s trend order (vote velocity with time decay).

  • limit — 1–25, default 10.
  • Returns polls (standard payloads, each also carrying trend_score) and count.
GET/v1/sentiment/categories/:category

A sentiment snapshot for one poll category over a time window.

  • :category — a MILA category id, e.g. politics, sports, tech. Unknown ids return 404 not_found.
  • days — 1–90, default 30. Only polls created inside the window count.
  • Returns window, poll_count, polls_with_votes, total_ballots, and top_polls — up to 10 standard payloads, most ballots first.
GET/v1/sentiment/search?q=

Public polls whose question text contains the query.

  • q — required, minimum 2 characters; shorter or missing returns 400 invalid_query.
  • limit — 1–25, default 10.
  • Returns query, count, and results — standard payloads, most ballots first.

The standard poll payload

  • poll_id, question, category, categories, format, status (active or closed)
  • public_url — the poll’s public page on MILA
  • window — opened_at, closes_at, closed_at (null while open)
  • sample_size — total ballots; sample_state — "sufficient" or "insufficient_sample"
  • options[] — each with id, label, position, votes, and — only at 10+ ballots — share_percent (one decimal)
  • Slider polls return options: [] and, above the floor, average_intensity

05 / Rate limits & errors

Limits and error codes

Per key: 60 requests per minute and 10,000 requests per day, counted durably from the API’s usage log — every authenticated request is recorded (key, route, status), so the caps hold across the whole fleet, not just one server. Going over returns 429 rate_limited.

HTTPCodeMeaning
401invalid_keyMissing, malformed, or unknown API key.
401key_revokedThis key has been revoked. Contact MILA for a replacement.
403scope_requiredThe key lacks the sentiment scope these endpoints require.
404not_foundPoll or category not found, or the poll is not public.
400invalid_querySearch query missing or under 2 characters.
429rate_limitedOver 60 requests/minute or 10,000 requests/day for this key.
